# Roadmap and Definition of Done

**Start:** 2026-10-31 · **Target:** 16 weeks (adjust to actual progress).  
**Cadence:** 5–6 learning sessions plus one review/mini-project session per week.

## Weekly acceptance criteria

| Weeks | Evidence required |
| --- | --- |
| 01–02 | Hand-calculated examples, NumPy implementations, tests, loss curve |
| 03–04 | PyTorch/autograd exercises, trained MLP, tokenization/embedding experiments |
| 05–06 | Verified attention shapes, masking tests, transformer forward pass |
| 07–08 | Reproducible training config, checkpoints, held-out evaluation, documented limitations |
| 09–10 | Prefill/decode measurements, cache correctness tests, memory and latency tables |
| 11–12 | Controlled serving benchmarks with concurrency, throughput, TTFT/TPOT and p95/p99 |
| 13–14 | Retrieval quality evaluation, tool-use tests, failure cases |
| 15–16 | API integration, security controls, load tests, metrics, final report |

## Daily learning checklist

- [ ] Understand the concept without relying on code alone
- [ ] Work through at least one numerical example
- [ ] Write implementation independently
- [ ] Test normal and edge cases
- [ ] Explain what failed and why
- [ ] Commit notes and code
- [ ] Decide whether there is a publishable insight

## Assessment rubric

Conceptual understanding 25%; mathematical reasoning 20%; implementation correctness 30%; experiments and reproducibility 15%; explanation and reflection 10%.

**Progress rule:** Only check off completed work backed by notes, code, tests or measurements. Unfinished work remains unchecked.
